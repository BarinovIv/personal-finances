# Учёт финансов

Личное приложение для быстрого учёта расходов и доходов с телефона. Словарь предметной области — в [CONTEXT.md](CONTEXT.md), архитектурные решения — в [docs/adr](docs/adr).

## Команды

Нужен Node.js 22.13+ (используется встроенный `node:sqlite`).

```sh
npm install
npm run check      # проверка типов, тесты и проверка границ модулей — всё сразу
npm start          # собрать PWA и запустить сервер на http://localhost:8080
```

Отдельно:

```sh
npm run typecheck  # tsc
npm test           # vitest (тесты сервера — Effect-программы через @effect/vitest)
npm run boundaries # dependency-cruiser: границы пакетов
npm run build      # сборка PWA в packages/web/dist
npm run serve      # только сервер (без пересборки PWA)
npm run dev -w @fin/web  # vite с проксированием /api на сервер
npm run icons -w @fin/web # перерисовать иконки PWA
npm run seed       # заполнить локальную базу тестовыми данными (DB_PATH; не для прода)
```

PWA: манифест и иконки в `packages/web/public`, service worker — `packages/web/src/sw.ts`. Сборка вписывает в него список файлов оболочки и версию; оболочка открывается из кэша без сети, новая версия ставится в фоне и открывается со следующего запуска.

## Переменные окружения сервера

| Переменная       | По умолчанию          | Что это                                                       |
| ---------------- | --------------------- | ------------------------------------------------------------- |
| `PORT`           | `8080`                | Порт HTTP                                                     |
| `STATIC_DIR`     | `packages/web/dist`   | Папка со сборкой PWA                                          |
| `APP_LOGIN`      | `owner`               | Логин владельца при первом запуске: 3–32 символа из латиницы, цифр, `_` и `-`; регистр не имеет значения |
| `APP_PASSWORD`   | —                     | Начальный пароль владельца. Повторно применяется только при изменении значения; смена пароля в приложении переживает перезапуск |
| `DB_PATH`        | `data/finances.sqlite`| Файл SQLite (ADR-0003)                                        |
| `SECURE_COOKIES` | `true`                | Флаг Secure у cookie сессии; `false` — только для http не на localhost |
| `BACKUP_TELEGRAM_TOKEN`   | — | Токен Telegram-бота для еженедельной резервной копии всей базы |
| `BACKUP_TELEGRAM_CHAT_ID` | — | Чат владельца. Без обеих переменных отправка резервной копии выключена |

Локально: `APP_LOGIN=owner APP_PASSWORD=секрет npm start`. При обновлении прежняя база и сессии переходят владельцу без потери данных; на существующих устройствах локальные данные закрепляются за первым вошедшим пользователем.

Владелец приглашает пользователей из «Настройки → Пользователи». Приглашение действует 7 дней и используется один раз; открытой регистрации нет. У каждого пользователя свои операции, категории, настройки и регулярные операции. Забытый пароль восстанавливается только через владельца: ссылка сброса действует 24 часа и закрывает прежние входы. Явный выход очищает данные устройства; истёкшая сессия сохраняет данные и очередь до повторного входа. Часовой пояс выбирается в настройках и синхронизируется; по умолчанию — `Europe/Moscow`.

Новые операции по регулярным шаблонам ожидают подтверждения. В ленте галочка подтверждает факт, крестик пропускает только эту операцию, карандаш меняет только её сумму и при сохранении подтверждает её. Шаблон и суммы следующих месяцев не меняются. До подтверждения доход не учитывается, а расход остаётся в предстоящих списаниях и резервирует свободные деньги. Дата остаётся запланированной; уже созданные до обновления операции считаются подтверждёнными. Новая ожидающая операция мягко подсвечивается при первом показе на устройстве.

## Telegram

Бот (`BACKUP_TELEGRAM_TOKEN`, `BACKUP_TELEGRAM_CHAT_ID`) отправляет владельцу только еженедельный бэкап: каждый понедельник в 03:00 по Москве, согласованный снимок всей базы (`VACUUM INTO`), сжатый gzip. Восстановление — в разделе «Деплой». Если сервер в этот момент не работал, пропущенное не догоняется; сбой отправки пишется в лог и не роняет сервер. Пользовательских подключений Telegram, сводок и сброса пароля через бот нет.

## Деплой

Приложение работает на Amvera: https://finances.example.com (проект `personal-finances`, регион Moscow-0, тариф «Начальный», один экземпляр — ADR-0003).

- Amvera подключена к этому репозиторию через GitHub-вебхук: пуш в `main` запускает сборку по `Dockerfile` и передеплой. Настройки сборки и запуска — в `amvera.yml`.
- База лежит на постоянном диске Amvera (`/data/finances.sqlite`) и переживает передеплой.
- `APP_PASSWORD`, `BACKUP_TELEGRAM_TOKEN` и `BACKUP_TELEGRAM_CHAT_ID` заданы секретами в разделе «Переменные» приложения; остальные переменные заданы в `Dockerfile`.
- Бэкап приходит в Telegram каждый понедельник в 03:00 МСК (см. «Telegram»). Восстановление: распаковать `finances-ДАТА.sqlite.gz` и загрузить как `/data/finances.sqlite` (вкладка Data в Amvera, старые `-wal`/`-shm` удалить), затем перезапустить приложение. Бэкапы самой Amvera на тарифе «Начальный» не делаются.
- Логи сборки и приложения — раздел «Логи» в панели Amvera.

## Устройство кода

Код разбит на пакеты в `packages/` — deep modules. У каждого пакета одна открытая точка входа — `index.ts` в корне, реализация лежит в `src/`, тесты — в `test/`. Исключения: `web` — приложение, его никто не импортирует, поэтому точки входа у него нет (логика клиента и её тесты живут в `ledger` и `sync`); `server/main.ts` — запускаемый файл сервера рядом с его точкой входа. Тесты обращаются к пакету только через точку входа; импорт внутренностей чужого пакета запрещён. Это проверяет dependency-cruiser (`.dependency-cruiser.cjs`).

| Пакет        | Что внутри                                                                  |
| ------------ | --------------------------------------------------------------------------- |
| `domain`     | Общие типы и даты (Europe/Moscow), без зависимостей                         |
| `entry-line` | Разбор строки ввода                                                         |
| `ledger`     | `Ledger` — ядро клиента и главная точка тестирования: операции, подстановка категорий, дашборд. Хранилище в памяти или IndexedDB |
| `protocol`   | Общие Effect Schema протокола клиента и сервера                             |
| `sync`       | Клиентская синхронизация (Effect только здесь; наружу — обычные функции)    |
| `server`     | Сервер на Effect + `@effect/platform`, SQLite                               |
| `web`        | PWA на Preact                                                               |
