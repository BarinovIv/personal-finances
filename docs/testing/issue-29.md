# Тестирование issue #29

Дата: 1 октября 2026. Требования: [«Несколько пользователей: друзья по приглашению»](https://github.com/BarinovIv/personal-finances/issues/29). Проверена локальная ветка `main`, коммит `56d2410492ad9ef2c9d13c3fd68b21ce88ac9d25`.

**Результат:** проверенные сценарии реализованной многопользовательской части прошли. Полное соответствие issue не подтверждено: требования Telegram отличаются от текущего ADR; Web Push не реализован в проверяемой версии.

## Среда и метод

- Production-сборка `packages/web/dist`, созданная через `npm run build`.
- Отдельный сервер `http://localhost:4173`, SQLite `/tmp/finances-issue29-20261001.sqlite`. Рабочая база и production не использовались.
- Playwriter 0.7.0, Chrome for Testing 154.0.8037.92, macOS; viewport 390 × 844, светлая и тёмная темы.
- Проверки начались в Chrome через расширение. Соединение терялось при открытии локальной PWA. Часть сценариев выполнена через Playwriter в headless Chrome, затем работа продолжена в видимом Chrome for Testing через прямое CDP-подключение.
- Независимые устройства моделировались разными локальными origins одного сервера и отдельными профилями браузера. Разные вкладки одного origin не считались разными устройствами.
- Действия пользователя выполнены через UI. Дополнительно через браузер проверялись HTTP-ответы и состояние IndexedDB только на чтение.
- Для неотправленных изменений Playwriter блокировал `/api/sync`; для ошибки выхода — `/api/logout`. Это имитация недоступности API, а не проверка полного отключения сети.

## Расхождения с issue и ограничения

1. **Telegram: спецификация и реализация расходятся.** User stories 17, 22, 24–29 и 33 требуют самостоятельного сброса через Telegram, подключения/отключения чата и недельных сводок в часовом поясе пользователя. На экране входа есть только инструкция обратиться к владельцу, а раздела Telegram в настройках нет. Это согласуется с текущими [ADR-0005](../adr/0005-multiple-users-one-server.md) и [README](../../README.md): Telegram используется только для еженедельной резервной копии всей базы. Автотест Telegram проверяет именно отсутствие пользовательских сообщений. Для приёмки исходного текста issue нужно согласовать его требования с ADR либо реализовать эту часть.
2. **Web Push, user story 40, не проверен и отсутствует в этой версии.** В проверенной сборке нет настройки напоминаний и реализации подписок Web Push; требуется отдельная функциональность из #28. Изоляцию и снятие реальной push-подписки подтвердить нельзя.
3. Реальные iOS Safari/PWA, разделение хранилищ Safari и приложения с домашнего экрана, Telegram-доставка и production не тестировались. Мобильная проверка — viewport Chrome, а не физический iPhone.
4. TTL ссылок, миграция и аварийная смена пароля через окружение проверены существующими автотестами, без изменения часов или production-конфигурации.
