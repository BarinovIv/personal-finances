# Несколько пользователей на одном сервере, без сквозного шифрования

Приложением начинают пользоваться друзья владельца — до ~20 человек, бесплатно, только по приглашению. У каждого свои данные. Разворачивать себе отдельный сервер друзья не станут, поэтому все живут на одном сервере владельца: каждая запись на сервере принадлежит пользователю, и синхронизация отдаёт каждому только его записи.

Данные на сервере хранятся открытым текстом, и владелец технически может их видеть — пользователям об этом говорится при регистрации. Сквозное шифрование закрыло бы данные и от владельца, но сервер тогда не смог бы создавать регулярные операции (ADR-0002). Для круга друзей это того не стоит.

## Consequences

- ADR-0001 остаётся в силе: «последняя правка побеждает» по-прежнему достаточно, потому что конфликты возможны только между устройствами одного пользователя.
- ADR-0003 остаётся в силе: на ~20 пользователей хватает одного SQLite-файла и одного экземпляра сервера. Ночной бэкап содержит данные всех и уходит только владельцу.
- Регулярные операции создаются по каждому пользователю отдельно и в его часовом поясе. Telegram отправляет только резервную копию всей базы владельцу; сброс пароля выполняется по одноразовой ссылке от владельца.
- Переход к шифрованию позже потребует перенести создание регулярных операций на клиент и заново решать проблему дублей, ради которой принят ADR-0002.
